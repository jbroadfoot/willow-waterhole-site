TEXT WRAPPING
  css/styles.css gains:
    h1, h2, h3, .big, .disp            { text-wrap: balance }
    .cta p, .section-intro, p.lead,
    .discover-sub                      { text-wrap: pretty }
    .nw                                { white-space: nowrap }
  balance is effectively universal (Chrome/Edge 114+, Firefox 121+, Safari 17.5+) and is
  scoped to headings only -- past roughly six lines the rebalance becomes visible on load
  and costs performance. pretty is less settled: Firefox support varies by source, Chrome
  adjusts only the last few lines while WebKit re-evaluates the whole paragraph, so the
  same widow resolves differently by browser. Both are progressive enhancement; neither
  can cause overflow, and unsupported browsers wrap exactly as they do today.
  .stats span and .stats-ttd b already declared balance in v5.6; not duplicated.

  Two confirmed breaks fixed DETERMINISTICALLY rather than relying on pretty:
    anniversary.html  CTA -- <span class="nw">Willow Waterhole</span> so the name cannot
                      split across lines.
    thingstodo.html   "hear from&nbsp;you" -- binds the last two words so "you." cannot
                      strand on its own line. The real problem there was the widow, not
                      the link splitting; nowrapping the whole 27-character link would
                      have stranded a longer line and risked overflow on small screens.

  NOT done, on purpose: no blanket .nw on the 200+ "Willow Waterhole" occurrences, no
  max-width changes to shared containers, no hard-coded <br> tags.
